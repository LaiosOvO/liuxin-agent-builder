## 项目概述

本 reading doc 是 Phase 3 **终结性 plan** 的汇总型笔记。与前 9 个 plan 的 reading doc 不同，03-10 不读新 Dify 代码——它整合 Phase 3 全部 10 个 plan 的设计思路、Phase 1/2 已建立的 E2E 测试模式、以及 CLAUDE.md 2.5 P0 Safe Links bot regression 验证策略，沉淀为 5 个 Playwright spec 端到端验收 ROADMAP Phase 3 全 5 条 success criteria。

**E2E 关键发现：Dify 本身没做完整 Playwright HITL 端到端 spec**。Dify 的 HITL 验证主要落在 `api/tests/` 单元/集成测试层，没有浏览器视角的 token 邮件 → 点击 → 决策 → 流程推进 → 追踪页全链路。本项目按 user feedback_e2e_browser_harness 强制要求做 **Playwright via webapp-testing skill** 三层测试中 E2E 层补齐这一空缺。

## 测试模式总结（Phase 1/2 → Phase 3 沿用）

### 模式 1：默认 skip + 显式 opt-in（Phase 1 01-06 建立）

```typescript
const shouldRun = !!(process.env.RUN_E2E || process.env.E2E_FULL_STACK);
test.skip(!shouldRun, '需要 docker compose up + RUN_E2E=1');
```

**Why**：CI 默认环境无 docker-compose 全栈；smoke mode 仅跑 lint + unit + integration。RUN_E2E=1 才触发 Playwright 跑全套。

### 模式 2：beforeAll 准备测试数据 + 真实 API（Phase 2 02-10 建立）

```typescript
test.beforeAll(async () => {
  authCookie = await getAuthCookie();  // login or initialize
  workflowId = await createPublishedHitlWorkflow(authCookie);
});
```

**Why**：UI 拖拽创建 DSL 慢 + 脆弱；API 直接 POST DSL → publish 一步到位，省 30s+ / spec。

### 模式 3：mailhog 邮件捕获 + 链接提取（Phase 1 01-06 建立）

```typescript
await purgeAllEmails();
const email = await getLatestEmail(approverEmail, 15_000);
const link = extractLink(email, '/hitl/page/');
```

**Why**：MailHog SMTP 拦截真实发件 + REST API 反查邮件 = 真实 + 可重现。Phase 3 扩展 `extractTokensFromEmail()` 解析 3 个 button 的 token。

### 模式 4：page.setExtraHTTPHeaders 模拟 bot UA（Phase 3 新增）

```typescript
const botContext = await browser.newContext({
  extraHTTPHeaders: {
    'User-Agent': 'Mozilla/5.0 (compatible; AC-Detector-Tool/1.0; +safelinks.protection.outlook.com)',
  },
});
const botPage = await botContext.newPage();
await botPage.goto(deeplink);
```

**Why**：CLAUDE.md 2.5 P0 — Outlook Safe Links 扫描器以 bot UA 预 GET 链接；E2E 必须模拟此场景验证 jti 未被预消费。

### 模式 5：DB 状态断言 via backend API（Phase 3 新增）

```typescript
// admin API 查 hitl_tokens.used_at
const tokenStatus = await apiFetch<TokenStatus>(`/api/agent_builder/v1/admin/hitl-tokens/${jti}`, {
  cookie: adminCookie,
});
expect(tokenStatus.used_at).toBeNull();  // 未消费
```

**Why**：spec 不直接连 PG（脆弱 + 跨进程）。后端预留 admin API 查询 token 状态便于 E2E 断言。备选：直接连 DB 用 pg client（postgres npm 包）。

### 模式 6：Page Object 拆分（Phase 1/2 建立 + Phase 3 扩展）

- `pages/canvas.page.ts`（Phase 1）：画布操作
- `pages/instance.page.ts`（Phase 2）：实例详情 + SSE 订阅
- `pages/hitl.page.ts`（**本 plan 新增**）：公网决策页（不需要登录）— /hitl/<token> 路径
- `pages/tracking.page.ts`（**本 plan 新增**）：申请人追踪页 — /dashboard/instances/<id>/tracking

**Why**：locator 集中管理 + 多 spec 复用 + 重构时单点修改。

## Safe Links Bot UA 4 种测试串（CLAUDE.md 2.5 P0）

```typescript
const BOT_UAS = [
  // 1. Outlook Safe Links 真实 UA（CONTEXT §Specific Ideas）
  'Mozilla/5.0 (compatible; AC-Detector-Tool/1.0; +safelinks.protection.outlook.com)',
  // 2. Microsoft Defender Safe Links
  'Mozilla/5.0 (compatible; MicrosoftDefender/1.0)',
  // 3. Slackbot LinkExpanding
  'Slackbot-LinkExpanding 1.0 (+https://api.slack.com/robots)',
  // 4. Googlebot（虽然不会扫审批链接，但通用 bot UA 测试）
  'Mozilla/5.0 (compatible; Googlebot/2.1; +http://www.google.com/bot.html)',
];
```

每个 UA 需断言：

1. GET 返回 200 + bot_scan.html 内容（或 JSON `{bot_scan: true}` 协商）
2. 无 Set-Cookie 头（不签 hitl_session）
3. `hitl_tokens.used_at IS NULL`（jti 未消费）
4. Redis 内 `agent_builder:jti:<jti>` 未写 consumed 标记

接着用 **真实 Chrome UA** 用同一 token 访问 → 应该正常拿到决策页（jti 未被预消费）。
